## Findings and fixes

| Area | Finding | Implemented protection |
| --- | --- | --- |
| OAuth configuration | The actual client ID was in `omni-rate-limit/wrangler.toml`; a separate Secret upload could not replace the old plain-text binding. | Removed the value from TOML and saved it in ignored, user-restricted `.env.local`. The deployment helper validates configuration, builds the public frontend ID, and publishes the backend Secret with the same Worker version through a temporary user-restricted `--secrets-file`. It redacts deployment output and removes the temporary file. Remote inspection confirms all three credentials are `secret_text` bindings. |
| Provider credentials | Provider keys already used server-only environment names and existing Cloudflare Secrets. | Verified both Cloudflare provider secret names without displaying values. Exact-value scans cover local source/build artifacts; provider keys appear only in ignored `.env.local` and `.dev.vars`. Provider redirects are refused and raw upstream errors are withheld. |
| Source-control exclusions | Additional credential exports/backups needed protection. | Extended `.gitignore` for private configuration, key files, credential exports, backups, builds, Worker state, and test artifacts. Added `npm run audit:secrets` to check credential patterns/exact values and actual Git ignore behavior without staging files. |
| Quota boundary | Fixed windows permitted bursts across adjacent boundaries. | Replaced them with atomic rolling admission of five attempts in 60 seconds per verified Google subject, shared across text and images. Added old-counter migration, delayed-alarm protection, and fail-closed storage errors. |
| Identity/header abuse | Caller-controlled IP, identity, and malformed headers must not bypass auth/quota. | Quota uses the verified Google `sub`; IP/forwarded identity headers have no effect. Tightened bearer syntax and JWT checks. Exact production Origin checks reject missing/null/joined/mismatched origins; preflight headers/methods are restricted. Local API no longer trusts forwarded host headers. |
| POST payloads | Lenient fields/types and body handling allowed unsupported inputs. | Shared validation caps streamed bodies at 256 KiB, requires UTF-8 JSON, rejects unsupported compression, invalid lengths/encoding/JSON, prototype keys, unknown fields, control characters, invalid roles/types, and excessive content. Server constructs fixed provider payloads; clients cannot set endpoints, models, system roles, or tools. |
| Response/browser security | Static assets bypassed Worker headers; inline application styles needed CSP support. Actual GIS also injects an inline button stylesheet. | Routed all assets through the Worker, added fresh nonce CSP for HTML scripts/styles (including React styles), and disabled HTML caching. Added secure headers to API, assets, errors, and local server responses. Google sign-in/font hosts and the exact inspected GIS stylesheet SHA-256 hash are explicitly allowed; arbitrary inline style elements remain blocked. |
| Output and images | Returned content and image sources require safe rendering. | Browser test confirms hostile returned text remains literal. Image sources reject executable URLs, SVG/HTML data URLs, and HTTPS URLs with embedded credentials. Downloads omit credentials and referrers. |

Headers include `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Resource-Policy`, and popup-compatible `Cross-Origin-Opener-Policy`.

The production generation CORS allowlist contains only `https://omni-rate-limit.jaudianhabib879.workers.dev`. It permits generation preflight only for POST with Authorization/Content-Type, exposes Retry-After, and grants no CORS access to rejected origins.

## Remaining limits and release status

1. The current production deployment is `1c1f58f0-c544-4f96-9ac7-1d0455909048`. Audited hardening and backend OAuth Secret synchronization are complete. Google still rejects the deployed origin: save `https://omni-rate-limit.jaudianhabib879.workers.dev` under Authorized JavaScript origins on the Web client matching private `GOOGLE_CLIENT_ID`, then allow propagation. Real Google sign-in and production text/image generation through the hardened Worker must be verified before claiming generation is fully ready. Configuration-presence checks do not verify provider credentials or credits.
2. A Google OAuth client ID is inherently public in the browser. Its actual value is excluded from committed source, but users can inspect it in deployed assets. No Google client secret is required or stored for this flow.
3. Any provider keys shared previously outside private configuration must be rotated in provider dashboards and synchronized privately. This audit prevents detected repository leakage; it does not revoke already exposed credentials. Rotation has not been performed.
4. The limiter enforces the per-account rule; multiple valid Google accounts and infrastructure-level denial of service require separate operational controls. CORS is a browser control and cannot authenticate non-browser callers. Body validation does not eliminate natural-language prompt injection; generated text is escaped and the application exposes no privileged model tools.
5. CSP permits HTTPS image loads/downloads to accommodate provider/CDN URLs, including HTTPS connect destinations and inline style attributes used by React. Remote image hosts can observe retrievals and may refuse CORS downloads. Actual GIS script/button loading has been checked under deployed CSP; a real account popup has not. If Google changes the inspected inline stylesheet, its exact CSP hash must be reviewed and updated; scripts and other style elements remain restricted.
6. Scanning uses known values and credential patterns, excludes dependency directories/binary files, and cannot prove the absence of every unknown secret. The ignored legacy `.env.oauth.local` is unreadable under its earlier sandbox ACL; it was not rescanned or repaired. Earlier task records identify its contents as only the public OAuth ID. Deployment now reads accessible `.env.local` first and does not depend on that legacy file.

## API key follow-up audit — November 9, 2026

The initial source release is `a0d4ed1` on `main`. The follow-up inspected the actual Git index and reachable history, browser artifacts, provider request/error handling, local file permissions, live configuration responses, and Cloudflare Secret binding types.

**Finding fixed:** Vite's default file exclusions protected `.env` files but did not protect the ignored Worker `.dev.vars`. A loopback HTTP probe returned 200 and confirmed private configuration was served, without displaying any values. The same probe after adding explicit `server.fs.deny` exclusions returns 403 with no private configuration. Regression tests use synthetic files and verify ordinary, `?raw`, and `/@fs/` access cannot disclose credentials, backups, private Worker state, or Git metadata. Existing development servers must be restarted to load the fix. This confirms a local exposure path; it does not establish that another person retrieved the keys.

**Publication controls:** the scanner now reads staged blobs and all reachable branch/tag history, so `.gitignore`, working-copy edits, or deletion in a later commit cannot conceal a credential. Built browser artifacts are checked even though ignored. Local pre-commit/pre-push hooks are enabled in this checkout; other checkouts opt in with `npm run security:hooks`. Build and deployment helpers fail on detected leaks, and GitHub Actions runs the checks on pushes and pull requests. The scanner logs paths/labels only. Tests verify staged-only and deleted historical synthetic credentials are detected. CI has no access to private local values, so its detection uses recognizable patterns.

**Verified:** no provider keys detected in the released Git blobs or built frontend/extension. Cloudflare reports `GROQ_API_KEY` and `PIX_ROUTER_API_KEY` as `secret_text` bindings. Local `.env.local` and `.dev.vars` ACLs disable inheritance and allow only the current user. Live config/health and private-file HTTP probes disclose no known provider key; private-file paths return 404. Missing or forged authentication returns 401 and an untrusted origin returns 403. These probes make no authorized generation requests. Root and Worker dependency audits report zero known vulnerabilities.

**Remaining action:** rotate the existing provider keys if they were previously shared or if an unauthorized client accessed the vulnerable development server. Rotation/revocation requires each provider dashboard and has not been performed. Replace values privately in `.env.local`, upload through `npm --prefix omni-rate-limit run secrets:sync`, and update the separate ignored local Worker copy. Do not post replacement keys in chat. Key secrecy does not cap total spend across multiple valid Google accounts; use provider spending limits for that operational control. The legacy ignored `.env.oauth.local` remains unreadable and unscanned. No Cloudflare deployment was performed for this follow-up.
